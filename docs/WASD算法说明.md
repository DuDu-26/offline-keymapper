# WASD 轨迹算子：已恢复公式与独立实现

本说明依据原包在隔离环境正常加载后、从进程外部只读保存的原始 DEX（`457095c52c1055aa7df539284a34975718a667ad7c812b3cc1e4938c60435fcf`，3,704,036 字节），以及该字节码的 REA Java 派生视图和 smali 指令。原始 DEX 未修复任何字节。日期：2026-11-07。

已写入独立实现 `app/src/main/java/cn/offline/mapper/engine/JoystickTrajectory.java`。本文件只包含坐标与调度算子，通过 MoveSink 发送点，不加载原软件的授权库。原 UI 模式、游戏包名分支、按键生命周期和按下/释放也已核对，见下文控制器部分。坐标算法一致也不表示已证明游戏账号安全。

## 一、确定的目标点公式

原 `r3.d` 持有一个 `java.util.Random`，每次方向/半径变化生成目标，随后创建新的 `r3.e` 任务。每个任务另建一个 Random；这两个随机流不能合并。原 `r3.a` 是直接定位版本。

内部方向 1..8 依次是上、下、右、左、右上、右下、左下、左上。随机版本使用以 X 正方向为 0 的弧度角，再采用屏幕坐标 `y = centerY - sin(angle)*radius`。对应角为 `π/2, -π/2, 0, π, π/4, -π/4, -3π/4, 3π/4`。直接版本斜向用单精度 `(float)(sqrt(2)/2)`，并以 `(int)(radius*diagonal)` 向零截断。随机版本 sin/cos 保持 double 后再 `(int)`。

| 内部参数模式 | 终点整数偏角 | 半径倍率 | 终点每轴整数扰动 | 基础弯曲因子 | strong |
|---|---|---|---|---|---|
| 0（其他传值也落此分支） | -12..12 度，闭区间 | `1 + U×0.8` | -6..5 像素 | 0.35 | false |
| 1 | -15..15 度，闭区间 | `1 + U×1.2` | -10..9 像素 | 0.6 | true |
| 2 | -6..6 度，闭区间 | `1 + U×0.4` | -3..2 像素 | 0.18 | false |

这里的 U 为 `Random.nextDouble()`。不能把内部编号直接标为某个 UI 模式；UI 还包含游戏包名分支，由控制链报告给出。

按严格调用顺序：`nextInt(2A+1)-A`、`nextDouble()`、X轴 `nextInt(2J)-J`、Y轴同式。目标为 `cx + (int)(cos(theta)*R*multiplier) + jitterX` 和 `cy - (int)(sin(theta)*R*multiplier) + jitterY`。弯曲尺度 C 为 `(float)max(baseFactor*R, (multiplier-1)*R)`。

开启 twoPhase 后，还按顺序生成：第二目标偏角 `nextInt(9)-4`（-4..4 度）、半径 `(nextDouble()*0.07+0.95)*R`（名义 0.95..1.02 倍），第二弯曲尺度 `((nextFloat()*0.15f)+0.15f)*R`。注意最后这个范围是 0.15..0.30 倍，不能误读成“0.15..0.15”。

自定义只覆盖第一目标的真实整数角度范围，调用改为 `nextInt(max-min+1)+min`；原默认范围保持原随机调用数量与结果。它不暗中修改半径、路径类型、持续扰动或第二阶段角度。

## 二、路径不是单一固定曲线

原 helper `androidx.activity.g.g(random,a,b,scale)` 的真实运算是 `((nextFloat()*a)+b)*scale`，a 是跨度，b 是基数，二者不是 min/max。独立实现用 weighted 保留该语义与浮点运算顺序。

每任务构造时先消费 `nextInt(13)+33` 取得 33..45ms 的第一阶段总请求时长，再消费 `nextInt(16)+15` 取得 15..30 的基础采样点数。初始实际弯曲幅度：普通为 `((U*0.4)+0.8)*C`，strong 为 `((U*0.6)+0.9)*C`；距离 L 小于 2C 时，再乘 `max(0.5,L/(2C))`。

随后读取一次 `nextFloat()`，按照真实条件选择五族路径。阈值不是不受距离影响的固定概率：

1. `q < (strong?0.30:0.15)` 且 `L>2C`：生成围绕中点的五个弧状候选，使用其中三个作四阶 Bézier 控制点。
2. 若上一条件未命中，且 `q < (strong?0.50:0.25)` 且 `L>C`：生成逐渐收缩的旋转节点，分段线性插值，每点另有每轴 `((nextFloat()-0.5)*2)` 的噪声。分段点数是真正整数商，可能少于基础点数。
3. 否则当 `q < (strong?0.75:0.45)`：三控制点四阶 Bézier，控制点在主方向 0.2、0.5、0.8 的位置、横向符号交替。
4. 否则当 `q < (strong?0.90:0.65)`：两个控制点三阶 Bézier，沿主方向比例分别在 0.2..0.4、0.6..0.8，偏移到相反侧。
5. 剩余：三阶 Bézier，控制点比例分别 0.25..0.40、0.60..0.75，随机选择同侧或异侧。

所有 Bézier 采样先使用原三次缓动：t<0.5 时 `4*t*t*t`，否则令 u=2t-2，`u*u*u/2+1`。三阶与四阶系数运算和求和顺序按原字节码派生视图保留，避免重排导致单精度临界舍入差异。路径采样 `t = (float)i/(float)N`，不是整数除法。坐标 `Math.round(float)` 后按含端点的 `[10,width-10]`、`[10,height-10]` 裁切。原 Rect 的 right/bottom 在这里作为 Math.min 数值上限使用，不能拿 Rect.contains 的右/下开区间语义替代。

## 三、时间分配、二阶段与持续按住

第一阶段每点先 sleep，再发 MOVE。总时长整除点数的商保留整数除法，余数按原浮点累计分配；最后还有原回填循环。`splitDurations()` 未简化为另一种均匀算法。

若存在第二目标：先 sleep 25..70ms，再由当前点生成第二段三阶 Bézier；第二段点数 8..14，总请求时长 45..80ms。控制点、弯曲因子与随机调用次序同原方法后半段。第二阶段完成后，持续扰动基准切换为第二目标；未开启时，以第一目标为基准。

持续按住不是继续朝边缘扩大：每次从基准点重新加独立 X/Y 整数扰动。普通 sleep 为 150..300ms（闭区间），每轴 -5..5 像素；strong sleep 为 120..260ms，每轴 -12..12 像素。每次结果仍按相同边界裁切。该循环在线程中断后结束。

每个 MOVE 更新共享 current 点并发送 sink，均在 `synchronized(current)` 内且先检查 interrupted。重复坐标仍产生一次 MOVE 调用，不能在算子层去重。方向或半径变化由外部取消旧任务、新建任务；新任务继承共享 current，而不是强制回中心。停止与抬起在控制器层取消 Future 后使用同一 current 锁，避免旧任务在 UP 后补发。

## 四、已核对的反编译陷阱

`algorithm/smali/r3.e.smali` 对以下点给出直接指令证据：

- 第233..237行：时长分配中的 N/余数为两次 int-to-float 后 div-float。
- 第764..774行：弧形控制点的 i/4 是浮点除法。
- 第882..886、1643..1647、1904..1908、2243..2247、2721..2725行：多处采样 i/N 都是浮点除法。
- 第1170..1176、1302..1306行：旋转节点比例和分段插值比例为浮点除法。
- 第215行总时长/N 以及第1253行旋转路径分段点数是 div-int，必须保留。
- 第2860行原常量 0x78=120，故不能仅依赖 Java 视图里 UMErrorCode 符号含义推测持续按住间隔。

JADX Java 局部把这些表达式显示为 i/N，是派生类型表示缺口；实现按真实 DEX 指令恢复浮点转换，没有为了轨迹好看改原算法。

原包名常量5442已在隔离设备中经p.abcdstr(5442)单点读取，值确认为com.tencent.tmgp.codev；未修改返回值、鉴权或原APK。证据在research/joystick-deep/controls/string5442/run-once/constant-observation.json。新版默认按当前配置保存的游戏包名选择；参数档手选属于新增的透明设置，可显式覆盖自动选择。

随机模式首次按下使用独立共享Random：每轴原坐标加nextInt(60)-30，因此偏移是[-30,29]整数像素。普通模式首次按下不偏移。方向/半径变化取消旧Future、在同一共享current点上启动新任务，不抬起、不重置中心。W+S抵消，A+D抵消；剩余轴仍有效。最后有效方向归零时在最后位置UP，不先回中心。

半径默认90像素，原编辑界面主半径范围90..900；新版另保留既有比例布局和1..900像素自定义。半径开关0关闭、1长按、2按下切换；比例原范围30..300%，先用整数(R*percent)/100截断，开关状态变化时即使百分比为100也重建移动任务。停止、断连和重载配置会释放触点，关闭旧任务；多键盘按键所有权与紧急暂停由独立输入引擎管理。

新版还保留原服务触点size公式：nextFloat()*0.030000001f+0.02f，对每次事件的每个活跃触点重新采样，重复坐标不去重。size是Android事件字段，不是物理面积或摇杆半径。

本次恢复针对框架触摸注入前的WASD算子与状态行为。原生驱动注入通路、native末端发送实现、真实硬件延迟和游戏行为不在字节码对照覆盖范围；未据此判断账号安全。
